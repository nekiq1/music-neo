# Neo Music

Сайт, Telegram Mini App и бот в одном проекте. Дизайн — Liquid Glass (тёмная и светлая тема, цвета фона берутся из обложки), React 19 + Tailwind 4 + компоненты в стиле shadcn/ui. Сервер — один Node-процесс без зависимостей.

## Запуск

```bash
npm install
cp .env.example .env     # заполняйте только то, что нужно
npm run build            # собирает фронтенд в dist/
npm start                # сайт + API + бот: http://localhost:3000
npm test                 # 26 тестов сервера и бота
```

Node 20+. Для разработки: `npm run dev` (пересборка при изменениях).

## Источники музыки

| Источник | Ключи | Что играет |
|---|---|---|
| Deezer | не нужны | фрагменты 30 с, чарт на главной |
| iTunes / Apple Music | не нужны | фрагменты 30 с, топ региона (`REGION`) |
| Audius | не нужны | **полные треки** независимых артистов |
| SoundCloud | `SOUNDCLOUD_CLIENT_*` | полные треки (официальный API, нужна заявка) |
| Яндекс Музыка | `YANDEX_TOKEN` | полные треки, **выбор битрейта** (неофициальный API) |
| Spotify | `SPOTIFY_CLIENT_*` | каталог; звук подбирается из Deezer/Audius/iTunes |
| Сообщество | `PB_URL` | треки из PocketBase (только чтение) |

Источник без ключей не отображается как «включён». Падение одного сервиса не ломает поиск: ошибка запоминается на 30 секунд, чтобы мёртвый источник не тормозил каждый запрос.

## Качество (Авто / Высокое / Среднее / Экономия)

Настройки → «Качество». Что меняется на самом деле:
- **Все источники:** размер обложек, предзагрузка следующего трека (только «Высокое»), лёгкие эффекты (только «Экономия»). «Авто» смотрит на тип сети и режим экономии трафика.
- **Яндекс Музыка:** реальный битрейт потока (минимум / ~192 / максимум кбит/с).
- **Deezer, iTunes, Audius, SoundCloud:** сервис отдаёт один поток, его качество изменить нельзя. В плеере показывается фактический формат и битрейт.

## Telegram

1. @BotFather → `/newbot` → `BOT_TOKEN`. Включите inline-режим (`/setinline`).
2. Разместите сайт по HTTPS, укажите `WEBAPP_URL`. `/newapp` → короткое имя → `BOT_APP_SHORTNAME` (даёт ссылки `t.me/бот/приложение?startapp=…`, работают и в группах).
3. `npm start` запускает бота. Он умеет: поиск сообщением, карточку трека, отправку аудио, inline-поиск `@бот запрос`, кнопку Mini App в меню.

**@loaditbot.** Боты не могут писать другим ботам, поэтому автоматически передать трек загрузчику нельзя. Вместо этого в боте и в приложении есть кнопка «Скачать через @loaditbot»: она копирует ссылку на трек и открывает чат с загрузчиком. Имя бота меняется в настройках (`LOADER_BOT`).

**Синхронизация.** Внутри Telegram избранное, плейлисты и настройки сохраняются на сервере (`data/users/`) и переносятся между устройствами. Сервер проверяет подпись `initData` (HMAC) и срок её жизни, чужие данные прочитать нельзя.

## ВКонтакте

Официального публичного API для поиска и воспроизведения аудио ВК нет, поэтому поиск через ВК не используется. Реализовано «Поделиться во ВКонтакте» через публичную ссылку `vk.com/share.php` (токены не нужны).

## Безопасность

CSP с хэшем inline-скрипта, `frame-ancestors` только для приложения и Telegram, лимит запросов на IP (`RATE_LIMIT`, за прокси включите `TRUST_PROXY=1`), таймауты внешних запросов, защита от выхода за пределы `dist/`, ограничение размера данных синхронизации.

## Что изменилось по сравнению с прошлой версией

Удалены неработавшая React-заготовка (`src/`, `bot/`, `supabase/`) и старый ванильный фронтенд. Не перенесены вход по email и загрузка собственных треков через PocketBase: вместо них синхронизация через Telegram. `pb_schema.json` оставлен для чтения каталога сообщества.
